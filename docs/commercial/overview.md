## Принцип изоляции

Коммерческий проект изолирован от домашней инфраструктуры (S1 — OpenVPN-хаб для family/friends).
На S1 ничего из коммерческого проекта не размещается, домашний OpenVPN не меняется.

Исключение — S2: физически общий хост (домашний Pi-hole + выходная нода коммерческого проекта).
Разделение — процессами и firewall (`ufw`), см. [../shared/networking/iptables-s2.md](../shared/networking/iptables-s2.md).
⚠️ У S2 709 MiB RAM — при росте коммерческого трафика выносить exit на отдельный VPS.

## Схема канала

```
Клиент (Happ / V2Box / v2rayNG — ядро Xray-core)
  │  VLESS + Reality (SNI www.cloudflare.com), :443
  ▼
S_RU (Xray, routing):
  ├─ geosite:category-ru, geoip:ru ───────────► direct (выход с IP S_RU)
  └─ всё остальное ─► to-s2-relay (VLESS+TLS, pin сертификата) ─► S2:10001 ─► direct ─► интернет
```

Подписки клиентам отдаёт только Panel (`https://netru.ru.net:2096/…`, путь подписки секретный и в документации не хранится).

## Geo-split (серверный, с 01.10.2026)

- Шаблон Xray на S_RU: `domainStrategy: IPIfNonMatch`; правила — api → api, `geoip:private` → blocked, bittorrent → blocked, `geosite:category-ru` → direct, `geoip:ru` → direct.
- Тег RU-доменов — `geosite:category-ru`; `geosite:ru` недопустим (категории `RU` в `geosite.dat` нет).
- Компромисс: RU-сервисы видят IP дата-центра S_RU, а не IP клиента. Банки и Госуслуги при проверке 01.10 работали, но Госуслуги 21.10.2026 недоступны (раздел «Госуслуги через VPN» ниже). Запасной вариант — клиентский geo-split через JSON-подписку Panel.
- Детали, процедура отката и тесты — [operations-log.md](operations-log.md), «Сессия 01.10.2026».

## Клиенты и настройки

- Поддерживаются только клиенты на ядре **Xray-core** (REALITY на Xray ≥ v26.9.8 требует
  `X25519MLKEM768` key share в ClientHello, которого нет в `sing-box`-based клиентах).
- Рекомендуемые: **Happ** (iOS/Android/macOS/Windows/Linux — основной), V2Box, OneXray (iOS),
  V2ray VPN Client: Xray Vless (Android), v2rayNG (Android, вне маркета, GitHub-релизы).
- НЕ поддерживаются (ядро `sing-box`, несовместимость с REALITY): Hiddify, Shadowrocket,
  Karing. Диагностика и источник — [operations-log.md](operations-log.md), «Сессия 06.10.2026».
- Mux включён на клиенте (TCP+XUDP, concurrency 8).
- TLS fingerprint: `firefox` — обязателен для МегаФона.
- Reality: dest/SNI `www.cloudflare.com` (SNI `ozon.ru`/`vk.com` блокировал МегаФон). Ключи Reality в документации не хранятся.

## Резервный вход AmneziaWG (зафиксирован 20.10.2026)

- Инбаунд `AmneziaWG` (протокол `amneziawg`, 443/udp) создан оператором на ноде S_RU: id 3 на ноде, id 7 на Panel (`node_id` совпадает с `reality-entry`, то есть узел S_RU). Назначение — резервный вход для клиентов; 443/udp не пересекается с Reality на 443/tcp.
- Сокет 443/udp держит процесс `x-ui` (не `xray`). В `ufw` на S_RU есть правила 443/udp (v4 и v6) без комментария; когда они появились, не установлено.
- На S_RU есть сетевой интерфейс `amn0` (172.29.172.1/24; при проверке 20.10.2026 в состоянии DOWN); связь с работой инбаунда не установлена.
- В подписку инбаунд не исключён (`exclude_from_sub=0`); привязан один клиент — тестовый клиент оператора (комментарий «Mars»). У `reality-entry` клиентов 10.
- Проверка geo-split клиентским тестом (оператор, приложение AmneziaWG): зарубежный сайт (2ip.io) показывает IP S2 `77.105.161.151`, RU-сайт (yandex.ru/internet) — IP S_RU `31.77.169.67`. Прежнее утверждение «AmneziaWG без доработки не даёт geo-split» для этого инбаунда не подтвердилось; механизм не исследован.
- Приложение AmneziaWG не принимает ссылку подписки (ошибка), работает только готовая конфигурация. Как выдавать вход обычным клиентам, не решено.
- Не проверено: поведение Happ и других Xray-клиентов при записи `amneziawg` в подписке; другие AmneziaWG-приложения; механизм geo-split; подключения от операторов МТС и МегаФон.
- Параметры и ключи AmneziaWG в документации не хранятся.

## Госуслуги через VPN (диагностика 21.10.2026)

- Наблюдение оператора: Госуслуги не открываются через VPN ни в Happ, ни в AmneziaWG. Ping с телефона через VPN не проходит (ICMP через VLESS/Reality обычно не передаётся): для проверки ping не годится, нужен TCP-тест или открытие сайта.
- GSLB Госуслуг отдаёт разные IP в зависимости от резолвера: устройство напрямую получило `109.207.2.205`, при включённом VPN — `213.59.253.8` (совпадает с ответом резолвера на S2: DNS клиента в туннеле, по-видимому, резолвится на стороне S2).
- TCP 443 к `109.207.2.205`, `109.207.9.205`, `213.59.253.8`, `213.59.254.8` не устанавливается ни с S_RU, ни с S2, ни с S1 (контроль `ya.ru` с S_RU и S2 отвечает). Вывод: адреса серверов недоступны для Госуслуг независимо от маршрутизации; правило `domain:gosuslugi.ru` → direct на S_RU не помогло бы (трафик вышел бы с адреса S_RU).
- Решение — вывод Госуслуг напрямую с устройства клиента. Тест оператора на одном устройстве (Happ): профиль с `DirectSites: ["domain:gosuslugi.ru"]`, `GlobalProxy: "true"`, `DomainStrategy: "AsIs"` и гео-файлами RoscomVPN (jsDelivr, зафиксированный релиз) — сайт открылся, Госуслуги показали предупреждение о включённом VPN. Вариант профиля с гео-файлами из GitHub (Loyalsoldier) выдал в Happ ошибку загрузки гео-файлов (причина не выяснена).
- Не проверено: приложение Госуслуг и вход через ЕСИА целиком; другие устройства и ОС; приём профиля устройствами после включения в Panel (обновление подписки и Reconnect); остальные Xray-клиенты (V2Box, OneXray, v2rayNG) и AmneziaWG — клиентский профиль Happ их не затрагивает.
- В Panel (21.10.2026) включена маршрутизация и задан минимальный профиль `Shtil-direct` (только `domain:gosuslugi.ru` напрямую; источник — `servers/panel/happ-routing/`, коммит `1cbad0c`). Заголовок `routing` подписки отдаётся при любом User-Agent (проверено `curl -I`: `Routing` и `Routing-Enable: true`). Настройка глобальная для всех клиентов Happ. Откат: выключить «Включить маршрутизацию» в Panel или вернуть бэкап `/root/x-ui.db.bak-20261021-pre-happ-routing`.

## Сертификаты и DNS

- Panel: Let's Encrypt для `netru.ru.net` (certbot, `certbot.timer`; действует до 14.01.2027).
- DNS: зона `netru.ru.net` на Cloudflare (режим «DNS only», NS `ali.ns.cloudflare.com`, `dexter.ns.cloudflare.com`) с 12.10.2026; DNSSEC включён в Cloudflare, но DS у регистратора не добавлен (pending) — см. `next-session-todo.md`.
- S_RU: IP-сертификат `31.77.169.67` (`acme.sh`, профиль `shortlived`, ~6 дней, HTTP-01 на 80/tcp). Продление перезапускает `x-ui` (Xray падает на секунды).
- S2 панель ноды (25307): IP-сертификат Let's Encrypt (`acme.sh`, shortlived, с 02.10.2026, `/root/cert/ip/`); продление перезапускает `x-ui` и рвёт relay на секунды.
- S2 relay: самоподписанный `/etc/x-ui/certs/server.crt`, на S_RU стоит pin (`pinnedPeerCertSha256`) — файл не менять.

## Принятые риски

1. 3x-ui официально позиционируется как проект «для личного обучения», не для продакшена (решение принято осознанно, пересмотреть при нестабильности).
2. Единственный канал S_RU→S2: при блокировке нужен резервный (OpenVPN/UDP, Shadowsocks-2022 — не реализован). Клиентский резервный вход AmneziaWG на S_RU:443/udp зафиксирован 20.10.2026 (geo-split подтверждён клиентским тестом, механизм не исследован) и канал S_RU→S2 не заменяет.
3. Whitelist-блокировка в жёстком варианте (только гос. сервисы) не решается архитектурой.
4. Лимит устройств — soft (по числу выданных конфигов), технически не enforced.
5. Антифрод триала — с 10.10.2026 держится ТОЛЬКО на `tg_id`/`trial_used` (номер телефона исключён из сбора — решение оператора, связка Telegram ID + username признана персональными данными по 152-ФЗ, избегаем сбора дополнительных ПДн). Риск обхода повторного триала ВЫШЕ, чем было при проверке по телефону — принимается для MVP.
6. Причина прежнего сбоя relay на `yandex.com` не найдена; сайт теперь идёт direct, другие зарубежные сайты не проверялись.
7. Платежи: Robokassa отказала самозанятому (15.10); у ЮKassa автоотправка чеков для самозанятых прекращена 29.12.2025 (по данным поиска, не проверено на нашей учётке) — схема чеков выбрана 20.10.2026 («Мой налог» с подтверждением админа, не реализована), приём реальных платежей не включён.
8. DNSSEC для `netru.ru.net` не завершён: DS в зоне `ru.net` отсутствует (проверено 17.10.2026).
