# Миграция коммерческого проекта: Marzban → 3x-ui

## Статус: Решение принято, техническая миграция не начата

## Суть решения (зафиксировано 25.09.2026, подтверждено 26.09.2026)

Переход с Marzban на **3x-ui** (`MHSanaei/3x-ui`, mainline-проект).
Причины:
- Единая панель для VLESS+Reality и AmneziaWG (резервный канал) с общей
  базой пользователей
- Встроенная поддержка multi-node (панель управляет удалёнными нодами)
- Marzban показал жёсткое ограничение: внешний доступ к веб-панели
  невозможен без публично доверенного TLS-сертификата (self-signed
  принудительно отклоняется кодом самого Marzban, `UVICORN_HOST`
  сбрасывается на `127.0.0.1`)

⚠️ **Риск, принятый осознанно**: README самого 3x-ui заявляет проект как
предназначенный для "personal learning" и прямо не рекомендует
использовать в продакшене. Решение использовать его в коммерческом
проекте принято, несмотря на это предупреждение — пересмотреть при
первых признаках нестабильности.

## Новая архитектура

| Роль | Сервер | IP | Домен |
|------|--------|-----|-------|
| Панель 3x-ui (БД, подписки, бот) | Новый, отдельный VPS | `31.77.173.218` | `netru.ru.net` |
| Входная нода (entry, RU) | S_RU (бывший Marzban-хост) | `31.77.169.67` | — (по IP, Reality) |
| Выходная нода (exit, EU) | S2 | `77.105.161.151` | — (relay, порт 8443) |

Панель-сервер намеренно минимальный (1 vCPU / 768 MiB / 10 GiB,
~94.5 ₽/мес) — не проксирует клиентский VPN-трафик, только веб-UI,
подписки и Telegram-бот.

## Открытые риски и находки из предыдущей сессии (25.09.2026)

Полная история конфигов/ключей Marzban-эпохи — в архиве:
[archive/s_ru-working-config-2026-09-25.md](archive/s_ru-working-config-2026-09-25.md)

Ключевое из архива, актуальное и для 3x-ui:
1. **SNI-блокировка Мегафона** для Reality-доменов `ozon.ru`/`vk.com`
   на S_RU — dest сменён на `www.cloudflare.com`. При настройке нового
   Reality-инбаунда на 3x-ui нужно сразу выбирать домены, не входящие
   в список заблокированных Мегафоном (проверить заново, список мог
   измениться).
2. **AmneziaWG как резерв не даёт geo-split** — трафик выходит напрямую
   с IP S_RU, не через relay на S2. Если резервный канал нужен с той же
   защитой (скрытие RU-IP для не-RU трафика), потребуется отдельная
   настройка маршрутизации самого AmneziaWG через S2.
3. **v2rayNG нестабильно работает** с текущим сервером (Hiddify — ок).
   Гипотеза про рассинхрон версий Xray-core не проверена. Стоит
   перепроверить на новом стеке 3x-ui/Xray.
4. **fail2ban на S_RU возможно не запущен** — не расследовано.
5. Решение: **новая пара ключей Reality** генерируется заново на 3x-ui,
   старый приватный ключ Marzban-эпохи не переносится (домен подписки
   меняется на новый панель-сервер в любом случае).
