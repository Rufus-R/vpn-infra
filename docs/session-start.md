## 1. Ключевые файлы для чтения в начале сессии

Оператор вставляет на S1 один блок целиком — чтобы ассистент не запрашивал файлы по одному:

```bash
date
cat /root/vpn-infra/docs/session-start.md
echo "=========== SYSTEM-STATE"
cat /root/vpn-infra/docs/system-state.md
echo "=========== OVERVIEW"
cat /root/vpn-infra/docs/commercial/overview.md
echo "=========== OPERATIONS-LOG"
cat /root/vpn-infra/docs/commercial/operations-log.md
echo "=========== TODO"
cat /root/vpn-infra/docs/next-session-todo.md
echo "=========== BOT"
cat /root/vpn-infra/docs/commercial/bot.md
echo "=========== ARCHIVE"
ls /root/vpn-infra/docs/archive/ /root/vpn-infra/docs/commercial/archive/
echo "=========== CHECKPOINTS"
ls -t /root/vpn-infra/docs/checkpoint-*.md 2>/dev/null | head -3
echo "=========== GIT"
git --no-pager -C /root/vpn-infra status --short
git --no-pager -C /root/vpn-infra log --oneline -5
```

- `system-state.md` — состояние системы: решённые проблемы, техдолг, открытые вопросы.
- `commercial/overview.md` — обзор коммерческого проекта.
- `commercial/operations-log.md` — операционный журнал (инциденты, процедуры, статус).
- `next-session-todo.md` — открытые задачи.
- `commercial/bot.md` — схема Telegram-бота, API 3x-ui, статус реализации (читать каждую
  сессию до завершения всех сценариев бота).
- Архивы (`docs/archive/`, `docs/commercial/archive/`) — для истории, при необходимости.
- Если есть свежий `docs/checkpoint-*.md` — прочитать его (`cat`) перед началом работы.

## 6. Внешний поиск информации (опционально)

Если для диагностики/проектирования нужна информация из открытого интернета (например, API
стороннего проекта, известные баги, актуальная документация), а прямой доступ в интернет
у ассистента отсутствует, можно сформировать точный запрос для стороннего поискового агента
(например, отдельного ИИ с доступом к вебу) — оператор выполняет поиск и вставляет ответ
в чат текстом.

**Правила использования** (подтверждено практикой 04.10.2026, см. `commercial/bot.md`,
раздел «Интеграция с API Panel»):
- Формулировать запрос с явными техническими деталями (название проекта, версия, конкретные
  эндпоинты/термины) — помогает агенту найти релевантные источники (issue, релизы, код).
- Результат такого поиска — **не проверенный на нашей инфраструктуре факт**, а гипотеза из
  внешнего источника. В документации помечать явно: что исследовано внешним агентом, что
  подтверждено собственной проверкой (пример маркировки — `bot.md`: «✅ исследовано
  (внешний агент)» vs «⚠️ не проверено на боевой Panel»).
- Если в ответе агента есть номера версий/issue — указывать их в документации (упрощает
  повторную проверку при расхождении с нашей установленной версией).
- Перед использованием найденной информации в продакшене — обязательна верификация на
  реальной инфраструктуре (тестовый вызов, тестовый клиент/конфиг), не доверять вслепую.

## 7. Формат работы ассистента в сессии

- **Heredoc:** каждый блок — свой уникальный EOF-маркер (не переиспользовать между командами
  в одной сессии), чтобы случайно не захватить лишний вывод или не оборвать блок раньше времени.
- **Порядок действий:** сначала предположения/теории и read-only проверки → сверка с
  оператором → только после этого правки → повторная проверка (`git diff`/`status`) перед
  коммитом.
- **Команды, ожидающие подтверждения/интерактивного ввода:** не писать в этом же ответе
  следующие команды — они не должны выполниться раньше, чем оператор увидит результат.
- **Формат каждого ответа ассистента** — три части:
  1. Предположения/теории (лаконично)
  2. Команды для оператора: выполняются на S1; к S2 и S_RU — через
     `ssh root@77.105.161.151` / `ssh root@31.77.169.67`; содержимое файлов — через `cat`
  3. Вопросы оператору, требующие решения (если есть)
- **Контекст сессии:** в конце каждого ответа — примерная оценка использованного контекста
  (лимит сессии выбирает оператор: 200k или 250k токенов, значение — в первом сообщении сессии).
- **Старт сессии:** чтобы не тратить лишние раунды, при выполнении `cat session-start.md`
  оператору стоит сразу приложить вывод всех файлов из раздела 1 (а не только сам
  `session-start.md`) — иначе ассистент в следующем ответе всё равно запросит их по одному.
- **Язык документации:** весь `docs/` ведётся на русском; команды и код — как есть.
- **Многострочные вставки:** `ssh` читает stdin и «съедает» следующие строки — в блоках с
  несколькими командами использовать `ssh -n`; у git — `--no-pager` (пейджер `less` может
  обрывать вывод; локальная настройка `core.pager cat` не версионируется).
