## 7. Инцидент S2 / S3 (29.10.2026, открыто)

0. **✅ Telegram-бот на Panel восстановлен 30.10.2026** — socks5 `tg-proxy` перенесён
   с S2 на S3 (inbound `in-38417-socks` в Xray, `TG_PROXY_URL` в `.env` на Panel,
   рестарт `netru-bot` 11:32 МСК). До этого бот не получал апдейты ~17 ч (29.10 ~18:00 —
   30.10 11:32 МСК; ~604 таймаута). Детали и откат — `checkpoint-2026-10-30-health-check-tgproxy-s3.md`.
   После снятия блокировки S2 решить: вернуть `TG_PROXY_URL` на S2 (S2 — основной
   exit-хост) или оставить S3 (тогда inbound на S2 вывести из эксплуатации).

1. **Туннель S1 ↔ S3 (`home-backup`) — гипотеза «сдвиг» ОПРОВЕРГНУТА, причина — DPI**
   (`checkpoint-2026-10-30-tunnel-s3-shift-refuted.md`). Установлено 30.10:
   - `Bad encapsulated packet length (16705 = 0x4141)` — это два байта `'A'` (`0x41`) из
     socat-зонда 29.10, прочитанные как big-endian length. Артефакт зонда, не баг протокола;
     анализ исходников OpenVPN 2.6.19 (`socket.c`, `packet_size_type`=uint16, `stream_buf`)
     подтвердил: ни сдвига, ни ошибки в разборе длины нет. Loopback-репродукция не нужна.
   - Реальный симптом: handshake/PUSH_REPLY/Data Channel проходят, затем data-пакеты
     не подтверждаются, обе стороны рвут сессию по `--ping-restart` (~61 с). Постоянный флап.
   - Матрица: plain TCP 8443/8444/9700/9900 с S3→S1 — **проходит** (в т.ч. rnd-payload);
     plain UDP 9444 S1→S3 — 0/20 при `ufw ALLOW`; plain TCP S1→S3 (инициатор S1) — connect
     timeout; OpenVPN TCP 8443 (prod), TCP 9443 (тест), UDP 9444 (тест) — handshake OK,
     дальше тишина. ICMP в обе стороны 0% потерь.
   - Вывод: блокировка не по порту и не по содержимому в общем случае, а по **профилю
     OpenVPN-трафика** на пути S1↔S3 (после рукопожатия). Согласуется с DPI/TSPU. Требует
     подтверждения с нейтрального VPS.
   **⭐ 30.10 проверено: инверсия направления РАБОТАЕТ.** Тестовый стенд (одноразовый PKI в /tmp, прод-параметры
   8443/TCP + AES-256-GCM): сервер на S1, клиент на S3 → handshake OK, ping 15/15 и 12/12, 0 флапов за 4+ мин,
   3.6 МБ без потерь, MTU 1150 OK. Прод не тронут. Детали — checkpoint-2026-10-30-tunnel-s3-reversed-direction.md.
   **Приоритетное решение:** перевести резерв S1↔S3 на сервер-S1/клиент-S3 (зеркало прод-параметров,
   tls-auth/tls-crypt tls-crypt-home.key, tun-mtu 1300, keepalive 10 60) — по кнопке оператора.
   **Fallback (если инверсия не подойдёт), не применено:** TCP-OpenVPN в прямом виде не реанимировать. Варианты —
   (a) обернуть канал в Xray VLESS/Reality TCP 443 (S3 уже имеет xray, S1 — нет, надо ставить);
   (b) WireGuard UDP — только после проверки UDP-проходимости с другого VPS (сейчас 0/20);
   (c) ICMP-туннель — не рекомендуется. Оценить нужность S1↔S3 вообще: резерв home-канала,
   бот уже ходит через socks5 `tg-proxy` на S3, коммерческий канал в порядке.
   Побочно: на S3 висит зомби-сокет 8443 в `FIN-WAIT-1` (ino:0) с ретрансмиссиями —
   следствие, не причина.
2. **OpenVPN-канал S1↔S2 не тронут** — домашний контур работает на S2 (Pi-hole, доступы).
   Задача после снятия блокировки S2 — переустановка S2, возврат relay как hot-standby
   (см. `checkpoint-2026-10-29-s2-outage-s3.md`).

## 6. Правила

- Перед любым `rsync`/`scp` на Panel сверять `WorkingDirectory` юнита
  (`/etc/systemd/system/netru-bot.service`) и `DB_PATH` (`grep DB_PATH /opt/netru-bot/src/.env`):
  инциденты 09–10.10 (деплой не в тот каталог, два файла `bot.db`).
- Не использовать `git add -A` (артефакт `secrets/.gitkeep`); `git --no-pager` для diff/log; в
  многострочных вставках `ssh -n`.
- Изменения firewall на S2 — только через `ufw` (NAT в `/etc/ufw/before.rules`); не
  использовать `iptables -I/-A` и без нужды `ufw reload` (после reload проверить
  `iptables -t nat -S POSTROUTING`: по одной строке на подсеть). Бэкап S2:
  `/root/fw-backup-20261001-143917/`.
- Не трогать `/etc/x-ui/certs/server.crt` на S2 (relay 10001, pin на S_RU). Рестарт x-ui рвёт
  Xray на секунды.
- Откат `x-ui.db` на S_RU — только через `/root/restore-xui-db.sh <бэкап>`:
  `/root/x-ui.db.backup-20261001-215924` (до geo-split),
  `/root/x-ui.db.good-geosplit-20261001-231259` (рабочее). На S2:
  `/root/x-ui.db.backup-s2-20261002-002336`.
- Тег RU-доменов — `geosite:category-ru` (не `geosite:ru`); правки geo-баз сразу проверять
  `xray run -test`.
- `secrets/.gitkeep` в `git diff --stat` (22 байта → 0) при пустом `git status` — артефакт фильтра `git-crypt` (проверено 20.10.2026: `git check-attr` показывает `filter: git-crypt`); не стейджить и не коммитить.
