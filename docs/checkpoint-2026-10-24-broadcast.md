# Чекпоинт 24.10.2026 — механизм рассылки сервисных сообщений

Продолжение `checkpoint-2026-10-23-referrals.md`, раздел «Следующий шаг». Статус: реализовано, задеплоено на Panel, проверено живой рассылкой; документация обновлена этим чекпоинтом и точечными правками `bot.md`, `system-state.md`, `next-session-todo.md`.

## Решения оператора 24.10.2026
- Рассылка только для сервисных сообщений (пробный период, срок подписки, изменения условий). Рекламные сообщения не поддерживаются: в согласии на ПДн рассылка не упомянута.
- Журнал доставок — две таблицы (`broadcasts`, `broadcast_deliveries`); ввод — FSM в админ-меню с предпросмотром; в первой версии две аудитории; окно «срок заканчивается» — 3 дня; прерванная рассылка после рестарта досылает только `pending`.
- Заблокировавшим бота пользователям дальнейших шагов нет: факт записан (ниже).

## Что сделано
- Коммит `ca57b7b`: миграция `0006` (таблицы `broadcasts`, `broadcast_deliveries`), модуль `app/broadcast.py`, интерфейс `app/handlers/broadcast.py` (отдельный роутер с фильтрами `ADMIN_IDS` на `callback_query` и `message`), кнопка «📣 Рассылка» в `admin_menu_keyboard()`, запуск `resume_broadcasts` в `app/main.py`.
- Сценарий: «🛠 Админ» → «📣 Рассылка» → аудитория (на кнопке число получателей) → текст одним сообщением (обычный текст, до 3500 символов, без «/» в начале) → предпросмотр (число получателей и `user_id`) → «🧪 Пробная отправка мне» → «✅ Отправить (N)» / «✏️ Изменить текст» / «❌ Отмена».
- Аудитории: `nosub` — без подписки и без пробного периода; `expiring` — подписка со статусом `active` или `trial`, срок заканчивается в ближайшие 3 дня. Всегда исключены: без согласия на ПДн, привязанные ручные клиенты (`linked_clients`), администраторы (`ADMIN_IDS`).
- Черновик хранится в БД (`broadcasts.status=draft`), FSM держит только ожидание текста (`MemoryStorage` не переживает рестарт).
- Запуск: `draft → sending` условным `UPDATE` и снимок получателей одной транзакцией (двойной запуск невозможен); отправка фоновой задачей с паузой 0,1 с; `TelegramRetryAfter` — ожидание и повтор (до трёх попыток), `TelegramForbiddenError` — `blocked`, прочее — `failed`; перед запросом в Telegram доставка получает `sending`; по окончании отчёт приходит администратору, создавшему рассылку (ровно один: отчёт отправляется только вызовом, который перевёл рассылку в `done`).
- При старте бота `resume_broadcasts`: доставки в состоянии `sending` (итог неизвестен) становятся `unknown` и не повторяются (дубль хуже пропуска), `pending` досылаются.

## Факт о двух недоставленных
- `users` 6 и 7 не получили сообщение: Telegram вернул `Forbidden`. Этот ответ означает и блокировку бота, и удалённый или деактивированный аккаунт — по ответу не различить. Их `trial_used` остаётся 0, пробный период им доступен, если они сами вернутся и нажмут `/start`. Решение оператора: фиксируем факт без дальнейших шагов; в `users` признак блокировки не добавляется (журнал хранит результат по рассылке).

## Не проверено
- Аудитория `expiring` с настоящими получателями (на тесте — только с подменённым сроком).
- Возобновление после рестарта посреди отправки и ветки `failed`/`unknown` — только на заглушке.
- Рассылка нескольким администраторам (отчёт получает только создавший рассылку).

## Ограничения первой версии
- Только текст: без разметки и кнопок, до 3500 символов; только две аудитории; рекламные сообщения не поддерживаются.
- Предупреждение Python 3.12 про `datetime.utcnow()` — как во всём коде бота (низкий приоритет).
